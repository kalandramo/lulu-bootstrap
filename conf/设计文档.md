# lulu-bootstrap conf 模块 — 设计文档（Design）

> 版本：v2（精简版）
> 日期：2026-08-12
> 范围：`d:/code/lulu-bootstrap/conf`（配置 Schema 与代码生成设计）
> 变更：相较 v1，大幅收敛契约面至 9 个核心子域，移除 AI / Broker / Registry / Script / Workflow 五域及对应 proto 文件。

---

## 1. 概述

`conf` 是 `lulu-bootstrap` 的**配置契约层**。用 Protocol Buffers 定义应用拓扑的强类型 Schema，经 buf 工具链生成 Go 绑定，运行期 `bootstrap` 包解析为 `lulu.App`。

### 1.1 设计原则

1. **Schema 即契约**：`protos/` 唯一事实源，`gen/` 仅由工具生成。
2. **声明式 + 可组合**：`optional` 表达可选/可组合子系统。
3. **类型安全优先**：优先强类型消息。
4. **生成代码纯净**：`gen/go` 不依赖业务/插件库。
5. **最小核心优先（v2 新增）**：未落地或在框架外演进的子系统先从契约中剥离，待稳定后回加。

---

## 2. 总体架构

```
用户配置 (YAML / JSON / .bin)
        │ LoadConfigFromFile / protojson / proto.Unmarshal
        ▼
conf/gen/go/bootstrap/v1  (generated .pb.go)  ← 10 文件
        │ 运行时解析
        ▼
bootstrap 包 (bootstrap.go / builder.go / *_builder.go)
        │ builder registry (string → builder func)
        ▼
lulu.App
```

### 2.1 工具链链路

```
protos/bootstrap/v1/*.proto
   │  buf build  (buf.yaml: module=protos)
   ▼  buf image → buf generate (buf.gen.yaml)
   buf lint / buf breaking (质量守护)
   ▼
gen/go/bootstrap/v1/*.pb.go  (10 个)
```

## 3. 工具链设计

### 3.1 buf.yaml

```yaml
version: v2
modules:
  - path: protos
```

### 3.2 buf.gen.yaml

```yaml
version: v2
managed:
  enabled: true
  override:
    - file_option: go_package_prefix
      value: github.com/kalandramo/lulu-bootstrap/conf/gen/go
plugins:
  - remote: buf.build/protocolbuffers/go
    out: gen/go
    opt: paths=source_relative
```

- **managed mode**：自动注入 `go_package`，统一前缀。
- **paths=source_relative**：`protos/bootstrap/v1/x.proto` → `gen/go/bootstrap/v1/x.pb.go`。
- **go_package 最终值**：`github.com/kalandramo/lulu-bootstrap/conf/gen/go/bootstrap/v1`。

### 3.3 生成约束

- 当前生成 10 个 `.pb.go`，对应 10 个 `.proto`。
- `gen/` 禁止手工编辑。
- **依赖管理变更**：`conf/go.mod`、`conf/go.sum` 已于 v2 删除，proto 运行依赖（`google.golang.org/protobuf`）改由仓库根 `go.mod` 统一管理。

## 4. Schema 设计

### 4.1 顶层：BootstrapConfig（9 字段）

`bootstrap.proto` 顶层消息字段重排为 1–9：

| # | 字段 | 消息 | 说明 |
|---|------|------|------|
| 1 | app | App | 应用元数据 |
| 2 | server | Server | 传输层（多协议） |
| 3 | config | Config | 配置中心（多源） |
| 4 | logger | Logger | 日志系统 |
| 5 | tracer | Tracer | 分布式追踪 |
| 6 | metrics | Metrics | 指标监控 |
| 7 | storage | Storage | 对象存储 |
| 8 | cache | Cache | 缓存 |
| 9 | database | Database | 数据库（多类型） |

> 移除域：registry(原4)、broker(原8)、ai(原10)、workflow(原11)、script(原13)。import 同步清理。

### 4.2 配置中心：Config（2 源）

`config.proto` 当前含 2 个 `optional`：

```
optional File file = 1;     // path / format / watch
optional Nacos nacos = 2;   // server_addrs / namespace / group / data_id / format
```

- **混合配置语义**保留：同一 `Config` 中可同时设置多源。
- v2 移除：fs / etcd / consul / apollo / kubernetes / redis / zookeeper / vault / http / env / oss / polaris。

### 4.3 传输层：Server（仅 HTTP）

`server.proto` 当前仅 `optional Http http = 1`：
- `addr`、`driver`(net/http / chi / gin / fiber)、`tls`(统一 TLS 子消息)、`middleware`。
- **HTTP 中间件（7 种，按字段顺序注册）**：
  - Recovery（`stack_trace`）
  - CORS（allowed_origins/methods/headers/exposed_headers/allow_credentials/max_age）
  - Logging（`skip_paths`）
  - RequestID（`header_name`）
  - Tracing（空消息，复用全局 TracerProvider）
  - RateLimit（`rate`/`burst`/`wait`）
  - Timeout（`default_timeout_ms`/`status_code`）
- **统一 TLS 子消息**：`File`(cert/key/ca path) + `Config`(cert/key/ca bytes) + `insecure_skip_verify`。

> 移除：HTTP/3、gRPC、GraphQL、SSE、WebSocket、TCP、UDP、KCP、Thrift、tRPC、WebTransport、Cron、HPTimer、MCP、SignalR、Socket.IO、WebRTC、Asynq、Machinery 及全部消息队列 Server。

### 4.4 日志：Logger（仅 Slog）

`log.proto`：`Type` 枚举仅 `TYPE_UNSPECIFIED` / `SLOG`；`optional Slog slog`（level / format / output_path）。
> 移除：Zap、Zerolog、Logrus、Charm、Phuslu、Glog、Hclog、Fluentd、Loki、Sentry、阿里云 SLS、腾讯云 CLS、AWS CloudWatch。

### 4.5 追踪 / 指标：Tracer / Metrics（不变）

- `tracer.proto`：`type=OTLP`，`Otlp`(endpoint/insecure/headers/sampler/sample_ratio)。
- `metrics.proto`：`type ∈ {PROMETHEUS, OTLP}`；prometheus(addr/path)、otlp(endpoint/insecure/headers/push_interval)。

### 4.6 对象存储 / 缓存（不变）

- `storage.proto`：`Minio` / `S3`。
- `cache.proto`：`Local`(FreeCache) / `Redis`。

### 4.7 数据库：Database（2 种）

`database.proto`：
- `SQL`（GORM/Ent 共用）：driver / source / migrate / enable_trace / enable_metrics / max_idle_connections / max_open_connections / connection_max_lifetime_seconds。
- `Elasticsearch`：addresses / username / password / cloud_id / api_key / service_token / certificate_fingerprint / enable_metrics / enable_debug_logger / max_retries / compress_request_body / discover_nodes_on_start / discover_nodes_interval_seconds。

> 移除：MongoDB、ClickHouse、Doris、OpenSearch、InfluxDB、Cassandra。

### 4.8 应用元数据：App（不变）

`app.proto`：id / name / version / env + `stop_timeout`(google.protobuf.Duration)。

### 4.9 已移除域速查

| 域 | 原 proto 文件 | 状态 |
|----|---------------|------|
| ai | ai.proto | 删除 |
| broker | broker.proto | 删除 |
| registry | registry.proto | 删除 |
| script | script.proto | 删除 |
| workflow | workflow.proto | 删除 |

## 5. 运行期解析接口（与 conf 的边界）

解析逻辑在 `conf` 之外，Schema 设计直接决定其形态（与 v1 设计一致，仅域数量收敛）：

### 5.1 Builder 注册表（`builder.go`）
每域维护 `map[string]BuilderFunc`，key 为小写类型字符串；注册 `RegisterXxxBuilder` / `MustRegisterXxxBuilder`，查找加 `sync.RWMutex`，`ListXxxBuilders()` 自省。

### 5.2 解析流程（`bootstrap.go`）
`Bootstrap(ctx, cfg)` 按序解析子域，累积 `lulu.Option` 与 `cleanup`：
```
resolveApp → resolveLog → resolveServer → resolveConfig
→ resolveTracer → resolveMetrics → resolveStorage → resolveCache → resolveDatabase
→ lulu.New(opts...)
```
出错回滚已注册 cleanup。

### 5.3 加载与解码（`bootstrap.go`）
`LoadConfigFromFile(path)` 按扩展名分发：YAML(`YAMLToJSON`+`protojson`)、JSON(`protojson`)、binary(`proto.Unmarshal`)。

### 5.4 上下文封装（`context.go`）
`Context` 封装 `cfg` / `app` / `cancel` / `cleanup` 及 `storages`/`caches`/`databases` map（按类型名索引）；`Cleanup()` 用 `sync.Once` 幂等；`Storage(name)/Cache(name)/Database(name)` 返回 `any`，需类型断言。

> 一致性备注（沿用 v1）：`Bootstrap` 返回值曾引用 `brokers`/`aiClients`/`workflows`/`scriptEngines`，但 `context.go` 仅含 `storages`/`caches`/`databases`，且相关 builder 文件曾在 git 中删除。v2 已移除这些域，`context.go` 应同步清理对应字段引用，避免编译缺口。

## 6. 命名与版本策略

| 项 | 约定 |
|----|------|
| proto package | `bootstrap.v1` |
| go_package | `.../conf/gen/go/bootstrap/v1` |
| 文件布局 | `protos/bootstrap/v1/<domain>.proto` |
| 类型 key | 小写字符串 |
| 字段编号 | 不复用/不删除；新增向后兼容 |
| 可选字段 | 一律 `optional` |

## 7. 演进与扩展指南

**新增一个配置源**（以 Etcd 为例，曾存在于 v1）：
1. `config.proto` 的 `Config` 新增 `optional Etcd etcd = 3;`（顺延编号）。
2. 新增 `message Etcd { ... }` 定义参数。
3. `buf generate` 重新生成。
4. builder 包实现 `ConfigAction` 并 `MustRegisterConfigAction("etcd", ...)`。

**回加一个已移除域**（如 broker）：
1. 新建 `conf/protos/bootstrap/v1/broker.proto`，定义 `message Broker { ... }`。
2. `bootstrap.proto` 重新 import 并加回字段（新编号，注意不与历史冲突）。
3. 同步实现 `conf` 外的 builder 与 `Context` 字段。
4. 调整 `buf breaking` 基线。

无需改动现有其余结构，符合 NFR-3。

---

## 8. 待办 / 一致性备注

1. **兼容基线**：本次移除了 5 个域并重排顶层字段编号，属破坏性收敛。建议以本轮提交作为 `buf breaking --against` 的新基线，旧 YAML 需按新编号重写。
2. **生成代码入库策略**：`gen/` 被 git 跟踪，建议明确为生成物或改 CI 生成 + `.gitignore`。
3. **依赖收敛**：`conf/go.mod`、`conf/go.sum` 已删，proto 依赖归并到仓库根 `go.mod`，需确认根模块已含 `google.golang.org/protobuf`。
4. **Context 字段清理**：移除 broker/ai/workflow/script 后，`context.go` 与 `bootstrap.go` 返回值中相关引用应一并删除。
5. **已注册 vs 预留**：v2 仅 `config` 域的 `file`/`nacos` 在运行期有 action；其余域的 builder 在 `conf` 外仓库实现，`conf` 仅定义契约。
