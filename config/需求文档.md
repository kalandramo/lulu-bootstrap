# config 子系统 — 需求文档（Requirements）

> 版本：v2
> 日期：2026-08-12
> 范围：`d:/code/lulu-bootstrap/config`（配置中心适配层 / config source builders）

---

## 1. 背景与目标

`lulu-bootstrap` 通过统一的 `BootstrapConfig` 启动应用。其中 `config` 子域负责**将配置源接入框架**——把外部配置（文件、Nacos 等）注册为可热更新的配置来源。

`config` 子系统是 `conf` 契约的**实现侧适配层**，每个源是一个独立 Go 子包，通过 `init()` 自注册到 `bootstrap.MustRegisterConfigAction`，由运行期 `resolveConfig` 调用。

**目标**：
- 将 `conf` 中声明的 `Config.File` / `Config.Nacos` 映射为可用的配置源实例。
- 支持混合配置（同一应用同时挂载多个配置源）。
- 业务代码通过 `import _ "..."` 以零侵入方式启用某个源。

---

## 2. 功能需求

### FR-1 配置源注册机制
- **FR-1.1** 每种子包在 `init()` 中调用 `bootstrap.MustRegisterConfigAction(typeKey, newAction)` 完成注册。
- **FR-1.2** `typeKey` 与 `types.go` 中的 `ConfigTypeFile` / `ConfigTypeNacos` 常量一致。
- **FR-1.3** `newAction(ctx, *v1.Config) (func(), error)` 返回 cleanup 闭包，框架在关闭时调用以释放资源。

### FR-2 文件配置源（file）
- **FR-2.1** 包路径：`config/file`，导入 `github.com/kalandramo/lulu-bootstrap/config/file`。
- **FR-2.2** 读取 `cfg.GetFile()`；为空返回错误 "file: config is nil"。
- **FR-2.3** 支持 `path`（`WithPath`）。
- **FR-2.4** 支持 `watch`（bool，开启 fsnotify 文件变更监听，`WithWatch(true)`）。
- **FR-2.5** 底层委托 `lulu-ext/config/file` 插件，创建失败返回 wrap 错误。
- **FR-2.6** cleanup 调用 `src.Close()` 释放。

### FR-3 Nacos 配置源（nacos）
- **FR-3.1** 包路径：`config/nacos`，导入 `github.com/kalandramo/lulu-bootstrap/config/nacos`。
- **FR-3.2** 读取 `cfg.GetNacos()`；为空返回 "nacos: config is nil"。
- **FR-3.3** `server_addrs` 必填，为空返回 "nacos: no server_addrs"；每个 addr 构造 `constant.ServerConfig{IpAddr, ContextPath:"/nacos"}`。
- **FR-3.4** `namespace` 映射到 `ClientConfig.NamespaceId`。
- **FR-3.5** 经 `nacos_client.NacosClient` 构建 config client（`config_client.NewConfigClient`）。
- **FR-3.6** `group` → `WithGroup`，`data_id` → `WithDataID`，委托 `lulu-ext/config/nacos` 创建源。
- **FR-3.7** 当前 Nacos 源 cleanup 为空函数（无显式关闭逻辑）。

### FR-4 错误处理
- **FR-4.1** 配置为空、必填项缺失、底层创建失败时返回明确的 wrap 错误。
- **FR-4.2** 未注册的配置源类型由 `bootstrap` 的 builder 注册表返回 "未注册" 错误（见设计文档）。

---

## 3. 非功能需求

| 编号 | 需求 |
|------|------|
| NFR-1 | **零侵入启用**：业务仅需匿名导入子包即可注册。 |
| NFR-2 | **自注册**：依赖 `init()` 机制，避免手动注册样板。 |
| NFR-3 | **资源可释放**：成功创建时返回 cleanup 闭包。 |
| NFR-4 | **与 conf 契约对齐**：读取 `v1.Config` 生成代码，不手写结构。 |
| NFR-5 | **隔离依赖**：各源独立子包，Nacos 依赖不污染 file 包。 |

---

## 4. 目录结构

```
config/
├── file/file.go        # file 配置源适配（自注册 ConfigTypeFile）
└── nacos/nacos.go      # nacos 配置源适配（自注册 ConfigTypeNacos)
```

> 注：旧版 `config/config_builder.go`（顶层聚合）已删除；聚合逻辑现位于 `bootstrap` 包的 `resolveConfig`。

---

## 5. 验收标准

1. `import _ ".../config/file"` 后，`BootstrapConfig.Config.File` 能被解析为文件配置源，且 watch 生效。
2. `import _ ".../config/nacos"` 后，`Config.Nacos` 能连上 Nacos 并拉取指定 data_id。
3. 同一 `Config` 同时配置 `file` + `nacos` 时，两者都被挂载（混合配置）。
4. 关闭应用时，file 源 `cleanup` 正确释放监听。

---

## 6. 风险与假设

- **假设**：v2 仅内置 file / nacos 两源；etcd / consul / apollo / vault 等源（v1 曾定义于 conf）暂未实现适配层。
- **风险**：Nacos cleanup 为空，若插件内部持有长连接，需补充优雅关闭。
- **注意**：`lulu-ext/config/*` 插件包为外部依赖，本子系统仅做桥接。
