# config 子系统 — 设计文档（Design）

> 版本：v2
> 日期：2026-08-12
> 范围：`d:/code/lulu-bootstrap/config`（配置中心适配层设计）

---

## 1. 角色定位

`config` 是 `conf.BootstrapConfig.Config` 的**实现侧适配层**。它位于 "声明（conf proto）" 与 "运行（bootstrap 框架）" 之间，把每个 `optional` 配置源映射为一个可注册、可释放的源实例。

```
conf.Config (proto, 声明)
      │ 运行期 resolveConfig 遍历已设置的 optional 源
      ▼
bootstrap.getConfigAction(typeKey)  ← 注册表查找
      │
      ▼
config/<source>/newAction(ctx, *v1.Config) (cleanup, err)
      │ 委托 lulu-ext/config/<source> 插件
      ▼
config.Source（已挂载）
```

---

## 2. 注册模式（统一约定）

每个子包遵循相同骨架：

```go
package <source>

func init() {
    bootstrap.MustRegisterConfigAction(bootstrap.ConfigType<Source>, newAction)
}

func newAction(ctx context.Context, cfg *v1.Config) (func(), error) {
    c := cfg.Get<Source>()           // 取对应 optional 子消息
    if c == nil { return nil, fmt.Errorf("<source>: config is nil") }
    // ...组装 lulu-ext 插件 Option...
    src, err := plugin.New(opts...)
    if err != nil { return nil, fmt.Errorf("<source>: create source: %w", err) }
    return func() { _ = src.Close() }, nil   // cleanup
}
```

- `MustRegisterConfigAction`：注册失败（重复 key / 未初始化）会 panic，适合 `init()` 阶段。
- 业务启用方式：`import _ "github.com/kalandramo/lulu-bootstrap/config/<source>"`。

## 3. 各源设计

### 3.1 file（`config/file/file.go`）
- 取 `cfg.GetFile()` → 校验非空。
- 组装 `lulu-ext/config/file` 的 `Option`：
  - `path` → `WithPath`
  - `watch`(true) → `WithWatch(true)`
- 创建 `filePlugin.New(opts...)`；失败 wrap 错误。
- cleanup：`src.Close()`（释放 fsnotify watcher）。

> 说明：格式（json/yaml/toml）由 `lulu-ext` 插件按 path 扩展名自动识别，适配层不显式传 format。

### 3.2 nacos（`config/nacos/nacos.go`）
- 取 `cfg.GetNacos()` → 校验非空。
- `server_addrs` 非空校验；构造 `[]constant.ServerConfig`，每个 `{IpAddr: addr, ContextPath: "/nacos"}`。
- `ClientConfig{ NamespaceId: namespace }`。
- 经 `nacos_client.NacosClient`：`SetClientConfig` + `SetServerConfig`，再 `config_client.NewConfigClient`。
- 构造 `lulu-ext/config/nacos` 的 `Option`：`group`→`WithGroup`，`data_id`→`WithDataID`。
- `nacosPlugin.New(client, opts...)`。
- cleanup：当前为空函数 `func() {}`（Nacos SDK 无显式 Close API，长连接由进程退出回收）。

---

## 4. 与 bootstrap 框架的接口

- **查找**：`bootstrap.getConfigAction(typeKey)` 在 `sync.RWMutex` 保护的 `configActions map[string]ConfigAction` 中查找；未注册返回错误。
- **遍历**：`resolveConfig` 对 `cfg.GetConfig()` 的每个已设置 `optional` 字段，按其 `typeKey` 调对应 action，累积 `cleanup`。
- **类型 key**：常量定义在 `types.go`：`ConfigTypeFile`、`ConfigTypeNacos`（小写字符串，与 conf 扩展一致）。

---

## 5. 依赖关系

```
config/file  → lulu-ext/config/file,  bootstrap, conf/gen/go/bootstrap/v1
config/nacos → lulu-ext/config/nacos, nacos-group/nacos-sdk-go/v2, bootstrap, conf/gen
bootstrap    → 提供 MustRegisterConfigAction / ConfigType* 常量
conf         → 提供 v1.Config 生成代码（契约）
```

- 各源子包相互独立，Nacos 的 SDK 依赖不会进入 file 包编译图。
- 适配层不持有具体源的类型，统一返回 `func()` cleanup，由 bootstrap 聚合。

---

## 6. 扩展指南

新增一个配置源（如 etcd）：
1. `conf/protos/bootstrap/v1/config.proto` 给 `Config` 加 `optional Etcd etcd = N;`。
2. `conf/types.go` 加 `ConfigTypeEtcd` 常量。
3. 新建 `config/etcd/etcd.go`：
   ```go
   func init() { bootstrap.MustRegisterConfigAction(bootstrap.ConfigTypeEtcd, newAction) }
   func newAction(ctx, cfg) (func(), error) { /* 委托 lulu-ext/config/etcd */ }
   ```
4. `buf generate` + 业务匿名导入即可生效。

无需改动 `resolveConfig` 聚合逻辑（依赖注册表动态查找），符合开闭原则。
