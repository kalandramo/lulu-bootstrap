# database 子系统 — 设计文档（Design）

> 版本：v2
> 日期：2026-08-12
> 范围：`d:/code/lulu-bootstrap/database`（数据库适配层设计）

---

## 1. 角色定位

`database` 是 `conf.BootstrapConfig.Database` 的**实现侧适配层**，把每个 `optional` 数据库配置构建为可用的客户端实例，并登记到 `Context`。

```
conf.Database (proto)
    │ bootstrap.resolveDatabase 遍历已设置的 optional
    ▼
bootstrap.getDatabaseBuilder(typeKey)
    │
    ▼
database/<type>/newBuilder(ctx, *v1.Database) (any, cleanup, err)
    │ 委托 tx7do/go-crud/<type>
    ▼
client 实例 → Context.databases[name]
```

---

## 2. 注册模式

```go
func init() {
    bootstrap.MustRegisterDatabaseBuilder(bootstrap.DatabaseType<X>, newBuilder)
}
func newBuilder(ctx context.Context, cfg *v1.Database) (any, func(), error) {
    c := cfg.Get<X>()
    if c == nil { return nil, nil, fmt.Errorf("<x>: config is nil") }
    // 组装 go-crud Option
    client, err := crud.NewClient(opts...)
    if err != nil { return nil, nil, fmt.Errorf("<x>: create client failed: %w", err) }
    return client, cleanup, nil
}
```

- 返回 `any`：适配层不暴露具体类型，业务经 `Context.Database(name)` 取回后类型断言。
- cleanup 用于释放连接资源。

## 3. 各适配设计

### 3.1 gorm（`database/gorm/client.go`）
- **依赖**：`github.com/tx7do/go-crud/gorm`。
- **Option 映射**（见需求文档 §FR-2）。
- **迁移模型桥接（重点）**：
  - 适配层维护包级 `migrateModels []interface{}` + `sync.RWMutex`。
  - `RegisterMigrateModel(model)` / `RegisterMigrateModels(models...)`：业务 `init()` 注册 PO。
  - `getMigrateModelList()`：返回副本，经 `gormCrud.WithGetMigrateModels` 注入。
  - 原因：`go-crud/gorm` 的 `initGormClient.doAutoMigrate` 调用 `c.getMigrateModels()`，而非 `resolveMigrateModels()`，需显式桥接。
- **cleanup**：`sqlDB, _ := db.DB.DB(); sqlDB.Close()` 关闭底层连接池。

### 3.2 elasticsearch（`database/elasticsearch/client.go`）
- **依赖**：`github.com/tx7do/go-crud/elasticsearch`。
- **Option 映射**（见需求文档 §FR-3），含认证（username/password/api_key/service_token/cloud_id/fingerprint）与发现策略（discover_nodes_*）。
- **cleanup**：当前 `func() {}`（go-crud 未暴露 Close）。

---

## 4. 模块化

`gorm` 与 `elasticsearch` 各有**独立 go.mod**，实现依赖隔离：
- gorm 模块仅依赖 `go-crud/gorm` 及其驱动。
- elasticsearch 模块仅依赖 `go-crud/elasticsearch`。
- 仓库根 `go.mod` 通过 `replace` / `workspace` 聚合（需确认根模块配置），或各子模块独立发布。

---

## 5. 与 bootstrap 框架接口

- **查找**：`getDatabaseBuilder(typeKey)` 在 `sync.RWMutex` 保护的 `databaseBuilders map` 中查找。
- **聚合**：`resolveDatabase` 对 `cfg.GetDatabase()` 各已设置字段构建实例，存入 `Context.databases`。
- **取用**：`Context.Database(name)` 返回 `any`（典型 name 即类型 key，如 `"gorm"`）。

---

## 6. 扩展指南

新增数据库（如 mongodb）：
1. `conf` 的 `database.proto` 加 `optional Mongodb mongodb = N;`。
2. `types.go` 加 `DatabaseTypeMongodb`。
3. 新建 `database/mongodb/client.go`（独立 go.mod，依赖对应 go-crud 包），`MustRegisterDatabaseBuilder`。
4. `buf generate` + 匿名导入生效。

---

## 7. 待办 / 备注

1. **多实例迁移隔离**：当前全局 `migrateModels` 对所有 GORM 实例共享，多库场景需改造为按实例/按 dsn 区分。
2. **ES cleanup**：建议补充连接关闭逻辑（如 go-crud 后续提供）。
3. **顶层聚合文件缺失**：旧 `database/database_builder.go` 已删除，聚合在 `bootstrap.resolveDatabase`。
