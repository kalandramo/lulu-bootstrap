# database 子系统 — 需求文档（Requirements）

> 版本：v2
> 日期：2026-08-12
> 范围：`d:/code/lulu-bootstrap/database`（数据库适配层 / database builders）

---

## 1. 背景与目标

`database` 子系统负责将 `conf.BootstrapConfig.Database` 中声明的数据库配置，构建为可注入业务代码的数据库客户端，并登记到运行期 `Context.Database(name)` 供检索。

v2 内置两种数据库适配：
- **GORM**（SQL，经 `tx7do/go-crud/gorm`）
- **Elasticsearch**（经 `tx7do/go-crud/elasticsearch`）

每个适配为独立子包，通过 `init()` 自注册到 `bootstrap.MustRegisterDatabaseBuilder`。

---

## 2. 功能需求

### FR-1 数据库构建注册
- **FR-1.1** 每子包 `init()` 调 `bootstrap.MustRegisterDatabaseBuilder(typeKey, newBuilder)`。
- **FR-1.2** `typeKey` 对应 `types.go` 的 `DatabaseTypeGorm` / `DatabaseTypeElasticsearch`。
- **FR-1.3** `newBuilder(ctx, *v1.Database) (any, func(), error)` 返回实例 + cleanup。

### FR-2 GORM 适配（gorm）
- **FR-2.1** 取 `cfg.GetSql()`；空返回 "gorm: sql config is nil"。
- **FR-2.2** `driver` → `WithDriverName`；`source`(DSN) → `WithDSN`。
- **FR-2.3** `migrate` → `WithEnableMigrate`；`enable_trace` → `WithEnableTrace`；`enable_metrics` → `WithEnableMetrics`。
- **FR-2.4** 连接池：`max_idle_connections`→`WithMaxIdleConns`；`max_open_connections`→`WithMaxOpenConns`；`connection_max_lifetime_seconds`→`WithConnMaxLifetime`。
- **FR-2.5** 自动迁移模型：业务通过 `RegisterMigrateModel` / `RegisterMigrateModels` 全局注册 PO 结构体，经 `WithGetMigrateModels(getMigrateModelList)` 桥接到 `go-crud/gorm`。
- **FR-2.6** 创建失败时 wrap 错误；cleanup 关闭底层 `*sql.DB`（`db.DB.DB().Close()`）。

### FR-3 Elasticsearch 适配（elasticsearch）
- **FR-3.1** 取 `cfg.GetElasticsearch()`；空返回 "elasticsearch: config is nil"。
- **FR-3.2** 连接参数：`addresses`→`WithAddresses`；`username`/`password`；`cloud_id`；`api_key`；`service_token`；`certificate_fingerprint`。
- **FR-3.3** 开关项：`enable_metrics`/`enable_debug_logger`/`compress_request_body`/`discover_nodes_on_start`（bool 直接映射）。
- **FR-3.4** `max_retries`(int)→`WithMaxRetries`；`discover_nodes_interval_seconds`→`WithDiscoverNodesInterval`。
- **FR-3.5** 创建失败 wrap 错误；当前 cleanup 为空函数。

### FR-4 多实例管理
- **FR-4.1** 多个 `optional` 数据库可在同一 `Database` 中并存，各构建为独立实例。
- **FR-4.2** 实例存入 `Context.databases` map（按类型名索引），业务经 `Context.Database(name)` 取用（返回 `any`，需类型断言）。

## 3. 非功能需求

| 编号 | 需求 |
|------|------|
| NFR-1 | **零侵入启用**：匿名导入子包即注册。 |
| NFR-2 | **自注册**：`init()` 机制。 |
| NFR-3 | **资源可释放**：GORM cleanup 关闭连接池；ES 待补。 |
| NFR-4 | **与 conf 对齐**：读取 `v1.Database` 生成代码。 |
| NFR-5 | **隔离依赖**：gorm 与 es 子包独立 go.mod，互不影响。 |

## 4. 目录结构

```
database/
├── gorm/
│   ├── client.go          # GORM 适配 + 迁移模型注册表
│   ├── go.mod / go.sum    # 独立模块（依赖 go-crud/gorm）
├── elasticsearch/
│   ├── client.go          # ES 适配
│   ├── go.mod / go.sum    # 独立模块（依赖 go-crud/elasticsearch）
```

> 注：旧 `database/database_builder.go`（顶层聚合）已删除；聚合在 `bootstrap.resolveDatabase`。

---

## 5. 验收标准

1. `import _ ".../database/gorm"` 后，`Database.Sql` 能构建 GORM 客户端并完成自动迁移（已注册 PO）。
2. `import _ ".../database/elasticsearch"` 后，`Database.Elasticsearch` 能连上 ES 集群。
3. GORM cleanup 在应用关闭时正确关闭连接池。
4. `Context.Database("gorm")` 可取回 GORM 实例（类型断言为 `*gorm.DB`）。

---

## 6. 风险与假设

- **假设**：v2 仅 gorm + elasticsearch；MongoDB/ClickHouse/Doris/OpenSearch/InfluxDB/Cassandra（v1 曾定义）暂无适配层。
- **风险**：GORM 迁移模型为全局注册（包级变量），多 GORM 实例会共享同一迁移模型集，不适合多库异构迁移场景。
- **注意**：ES cleanup 为空，长连接/连接池回收依赖进程退出。
