# oss 子系统 — 设计文档（Design）

> 版本：v2
> 日期：2026-08-12
> 范围：`d:/code/lulu-bootstrap/oss`（对象存储适配层设计）

---

## 1. 角色定位

`oss` 是 `conf.BootstrapConfig.Storage` 的**实现侧适配层**，将 `optional` 存储配置构建为对象存储客户端，登记到 `Context`。

```
conf.Storage (proto)
    │ bootstrap.resolveStorage 遍历已设置的 optional
    ▼
bootstrap.getStorageBuilder(typeKey)
    │
    ▼
oss/<type>/newBuilder(ctx, *v1.Storage) (any, cleanup, err)
    │ 委托 lulu-ext/oss/<type>
    ▼
storage 客户端 → Context.storages[name]
```

---

## 2. 注册模式

```go
func init() {
    bootstrap.MustRegisterStorageBuilder(bootstrap.StorageType<X>, newBuilder)
}
func newBuilder(ctx context.Context, cfg *v1.Storage) (any, func(), error) {
    c := cfg.Get<X>()
    if c == nil { return nil, nil, fmt.Errorf("<x>: config is nil") }
    pluginCfg := &plugin.Config{ ...来自 c.GetXxx()... }
    client := plugin.NewClient(pluginCfg)
    if client == nil { return nil, nil, fmt.Errorf("<x>: failed to create ...") }
    return client, func() {}, nil
}
```

## 3. 各适配设计

### 3.1 minio（`oss/minio/minio.go`）
- **依赖**：`github.com/kalandramo/lulu-ext/oss/minio`。
- 取 `cfg.GetMinio()` → 校验非空。
- 映射到 `minioPlugin.Config`：Endpoint / AccessKey / SecretKey / Token / UseSsl。
- `minioPlugin.NewStorage(cfg)`；nil 判定失败。
- cleanup：空函数。

### 3.2 s3（`oss/s3/s3.go`）
- **依赖**：`github.com/kalandramo/lulu-ext/oss/s3`。
- 取 `cfg.GetS3()` → 校验非空。
- 映射到 `s3Plugin.Config`：Endpoint / Region / AccessKey / SecretKey / Token / UseSsl / ForcePathStyle / Bucket。
- `s3Plugin.NewClient(cfg)`；nil 判定失败。
- cleanup：空函数。

> 设计要点：S3 比 MinIO 多出 `region` / `force_path_style` / `bucket`，适配层原样透传，便于对接 AWS S3 及兼容实现（CEPH、阿里云 OSS、MinIO 网关模式等）。

---

## 4. 与 bootstrap 框架接口

- **查找**：`getStorageBuilder(typeKey)` 在 `sync.RWMutex` 保护的 `storageBuilders map` 中查找。
- **聚合**：`resolveStorage` 对 `cfg.GetStorage()` 各已设置字段构建实例，存入 `Context.storages`。
- **取用**：`Context.Storage(name)` 返回 `any`（name 即类型 key，如 `"minio"` / `"s3"`）。

---

## 5. 依赖关系

```
oss/minio → lulu-ext/oss/minio, bootstrap, conf/gen/go/bootstrap/v1
oss/s3    → lulu-ext/oss/s3,    bootstrap, conf/gen/go/bootstrap/v1
```

适配层仅做配置桥接，不含对象操作业务逻辑。

---

## 6. 扩展指南

新增存储类型（如 cos）：
1. `conf` 的 `storage.proto` 给 `Storage` 加 `optional Cos cos = N;`。
2. `types.go` 加 `StorageTypeCos`。
3. 新建 `oss/cos/cos.go`：`MustRegisterStorageBuilder(bootstrap.StorageTypeCos, newBuilder)`，桥接 `lulu-ext/oss/cos`。
4. `buf generate` + 匿名导入生效。

---

## 7. 待办 / 备注

1. **cleanup 补全**：当前两适配 cleanup 为空，建议补充客户端关闭/连接回收（若插件支持）。
2. **Bucket 语义**：S3 的 `bucket` 在适配层透传，是否需在构建时校验非空或自动创建，建议明确。
3. **多实例**：同一应用同时挂 minio + s3 时，经 `Context.Storage(name)` 按名区分。
