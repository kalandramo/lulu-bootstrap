# transport 子系统 — 设计文档（Design）

> 版本：v2
> 日期：2026-08-12
> 范围：`d:/code/lulu-bootstrap/transport`（传输层适配层设计）

---

## 1. 角色定位

`transport` 是 `conf.BootstrapConfig.Server` 的**实现侧适配层**，把 `optional` 传输层配置构建为可运行的 `transport.Server`，注册到框架生命周期。

```
conf.Server (proto)
    │ bootstrap.resolveServer 遍历已设置的 optional
    ▼
bootstrap.getServerBuilder(typeKey)
    │
    ▼
transport/http/newBuilder(cfg *v1.Server) (transport.Server, error)
    │ 委托 lulu-ext/transport/http + 内置 std Driver
    ▼
transport.Server → 框架注册 + 启动
```

---

## 2. 注册与构建模式

```go
type Server = httpPlugin.Server   // 对外暴露别名

func init() { bootstrap.MustRegisterServerBuilder(bootstrap.ServerTypeHTTP, newBuilder) }

func newBuilder(cfg *v1.Server) (transport.Server, error) {
    httpCfg := cfg.GetHttp()
    if httpCfg == nil { return nil, fmt.Errorf("http: config is nil") }
    addr := httpCfg.GetAddr(); if addr == "" { addr = ":8080" }
    srv := httpPlugin.NewServer(addr, httpPlugin.WithDriver(newStdDriver()))
    if mw := httpCfg.GetMiddleware(); mw != nil { applyMiddleware(srv, mw) }
    for _, setup := range serverSetups { setup(srv) }   // 命令式回调
    return srv, nil
}
```

- `Server` 类型别名：业务/代码生成器只依赖本包，不直接依赖 `lulu-ext`。
- 返回 `transport.Server` 接口（来自 `github.com/kalandramo/lulu/transport`）。

---

## 3. HTTP 中间件注册（applyMiddleware）

严格按 proto 字段号顺序 `srv.Use(...)`：

| 顺序 | 中间件 | 配置 → 选项 |
|------|--------|------------|
| 1 | recovery | `stack_trace` → `WithStackTrace` |
| 2 | cors | origins/methods/headers/exposed_headers/credentials/max_age |
| 3 | logging | `skip_paths` → `WithSkipPaths` |
| 4 | requestid | `header_name` 非空才传 `WithHeaderName` |
| 5 | tracing | 无参 `Middleware()`（复用全局 TracerProvider） |
| 6 | ratelimit | `rate`+`burst` → `tokenbucket.New`；`wait` → `WithWait` |
| 7 | timeout | `default_timeout_ms`(缺省 5000) → `Middleware(d)` |

> 顺序即 proto 字段顺序，保证 Recovery 在最外层、Timeout 在内层等预期链序。

---

## 4. 命令式 Setup 回调

- `serverSetups []func(srv *Server)`：包级切片，保存所有注册回调。
- `RegisterServerSetup(fn)`：**追加**注册（推荐，供代码生成器 `init()` 使用）。
- `SetServerSetup(fn)`：**替换**所有（Deprecated，兼容旧调用）。
- 调用时机：`newBuilder` 创建服务器、应用声明式中间件后，返回框架前，按注册顺序调用 `setup(srv)`，用于 `srv.GET/POST` 路由与额外 `srv.Use` 中间件。

**代码生成器协作模式**：
```go
// generated_routes.go
func init() {
    httpAdapter.RegisterServerSetup(registerProtoRoutes)
}
```

---

## 5. 内置 std Driver

`stdDriver`（基于 `net/http`）实现 `httpPlugin.Driver` 接口：

- `Handle(method, path, handler)`：包装 `mux.HandleFunc`，方法不匹配返回 405。
- `Start(ctx, ln)`：构造 `http.Server{Handler: mux}`，goroutine `Serve(ln)`；`ctx.Done()` 触发 `Shutdown`（优雅关闭）。
- `Stop(ctx)`：`server.Shutdown(ctx)`。

> 说明：默认 std Driver 提供零额外依赖的基础能力；需更复杂的路由树/分组时，可在 `NewServer` 处传入 chi/gin/fiber Driver（通过 `WithDriver`）。

---

## 6. 与 bootstrap 框架接口

- **查找**：`getServerBuilder(typeKey)` 在 `sync.RWMutex` 保护的 `serverBuilders map` 中查找。
- **聚合**：`resolveServer` 对 `cfg.GetServer()` 各已设置字段构建 `transport.Server`，注册到 `lulu.New` 的 options。

---

## 7. 依赖关系

```
transport/http → lulu-ext/transport/http
               → lulu-ext/transport/http/middleware/{cors,logging,ratelimit,recovery,requestid,timeout,tracing}
               → lulu-ext/ratelimit/tokenbucket
               → kalandramo/lulu/transport
               → bootstrap, conf/gen/go/bootstrap/v1
```

## 8. 扩展指南

新增传输层（如 grpc）：
1. `conf` 的 `server.proto` 给 `Server` 加 `optional Grpc grpc = N;`。
2. `types.go` 加 `ServerTypeGRPC`。
3. 新建 `transport/grpc/grpc.go`：`MustRegisterServerBuilder(bootstrap.ServerTypeGRPC, newBuilder)`，委托对应 `lulu-ext/transport/grpc`。
4. `buf generate` + 匿名导入生效。

---

## 9. 待办 / 备注

1. **多实例索引**：当前 `serverBuilders` 按类型单注册，若需同一应用多 HTTP 实例（不同 addr/配置），框架需扩展按 name 索引。
2. **Driver 选择**：conf `server.proto` 的 `driver` 字段（net/http/chi/gin/fiber）当前在适配层**未消费**（始终用内置 std），需对接 `lulu-ext` 对应 Driver 构造逻辑。
3. **RateLimit 错误**：tokenbucket 创建失败时静默跳过限流中间件（仅 `err == nil` 才注册），建议改为显式告警/返回错误。
4. **Tracing 依赖全局**：tracing 中间件依赖框架已初始化的 TracerProvider，注册顺序需保证 resolveTracer 先于 resolveServer。
